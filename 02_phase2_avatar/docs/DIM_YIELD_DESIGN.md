# 实验：输入维数 vs 随机头像良率（盲测混合）

> 设计已实现并验证；训练进行中，完成后即可开标。

---

## 一、为什么要换指标

你说得对：目标是"**生成一张合理的随机头像**"，不是"精确还原指定脸"。

那么逐像素准确率是**错的指标**。证据：PCA-4 准确率只有 0.21（PCA-22 是 0.38），
但它的输出更平滑（同色率 74.5% vs 65.1%），而**真实数据的同色率是 77.6%**——
也就是说 PCA-4 在"看起来像真脸"这个维度上反而**更接近真实**。

真正的指标只有一个：**人看一眼，觉得这张脸能不能用**。

---

## 二、实验设计

### 训练

所有模型用**同一个配方**，只有输入维数不同。配方逐字取自当前最好的 32 输出模型
`results/shrink/s32_tv5`（准确率 0.7719、同色率 72.8%）：

| 项目 | 值 |
|---|---|
| 条件 | 前 k 个 PCA 系数（标准化），**无噪声** |
| 结构 | k → 256 → 256 → 32 连续值 |
| 损失 | MSE + 5.0×TV（在连续输出构造的软分布上）+ 对抗（权重 1.0） |
| 步数 / 批 | 12000 / 256 |
| 优化器 | Adam 3e-4，hid 256 |

**唯一变量是 k。** 所以良率差异只能归因于输入维数。

扫描 **k = 1, 2, 4, 8, 16**，加上已有的 **k = 22（s32_tv5）** 共 6 臂。

### 打标

`label.html?mix=1` —— **盲测混合模式**：

1. 每张脸**随机**从 6 个模型中挑一个
2. 用**全新随机参数**（无奖励引导，各臂等概率）
3. **不显示**是哪个模型
4. 每条标签记录 `model` 字段

这是**单评审、单场次、控制变量**的对照——你不可能因为"知道这是 PCA-4"而产生期望偏差。

### 统计

- 每臂算**良+优比例**及 **95% Wilson 区间**（小样本比正态近似稳）
- 每臂对 **PCA-22 参照**做**双侧 Fisher 精确检验**

## 三、已验证的工程细节

测试 `src/test_mix_mode.js` 全部通过：

| 检查 | 结果 |
|---|---|
| 两个臂确实交替出现 | PASS |
| 输入维数跟随所选臂（4 和 22） | PASS |
| **4 维臂真的忽略 pca[4..21]** | PASS |
| 奖励分数读数隐藏（防泄题） | PASS |
| 每条标签记录来源臂 | PASS |
| 采样是纯随机、非引导 | PASS |
| pca 向量仍保持 22 长度 | PASS |

**第三项是核心正确性检查**：给 4 维模型喂两个只在 index ≥ 4 处不同的向量，
输出必须**完全一致**。如果不一致，说明 `forward()` 还在读 22 个值，那整个实验就是废的。

为此我修了一个隐患：`forward()` 原本硬编码 `new Float32Array(22)`，现在改成 `IN_DIM`。

## 四、预期与判读

**如果低维柱显著高于 PCA-22**：
说明"生成合理随机头像"不需要那么多输入 → **输入侧可以从 22 个投掷器降到 4 个甚至 2 个**，
红石成本大降。

**如果 PCA-22 仍然最好**：
说明高层主成分虽然带来杂色，但也携带了让脸"像样"的信息，维度不能省。

**如果 1~2 维就够**：
那说明这个任务的有效自由度极低，值得重新考虑整个方案。

**无论哪种结果都结束了这个悬念**——这正是它的价值。

---

## 五、局限（先说清）

1. **样本量**：每臂至少需要 ~30 张才能给出有用的区间。若你打 180 张、6 个臂，每臂约 30 张，
   Wilson 区间宽度约 ±17 个百分点。**只能区分大差异**（比如 40% vs 70%）。
2. **单评审**：只有你的偏好。不过这正是我们要优化的目标，所以合理。
3. **"良"的标准会漂移**：如果中途改变标准，需要像上次那样保留纯随机对照。
   这次混合模式本身就是随机的，所以每臂受到的漂移影响是**等量的**，不会系统偏袒某一臂。
