## 引言

红石里绝大多数元件只认 0~15 的整数，比较器是唯一的例外。它有两个别的元件都没有的能力：

1. **做一次模拟运算**——比较大小，或者相减；
2. **承载大于 15 的值**——因为它的强度不在 4 位的方块状态里，而在方块实体的 `OutputSignal`（一个 int）里。

这两条加起来，就构成了“强模”这一整套东西的物理基础。但要真正用它，先得把它的**读数规则**钉死：
它从哪一面看、看到的是什么、什么时候会看不见容器。这一页只讲这些。

## 符号

| 符号           | 含义                                        | 取值                    |
| ------------ | ----------------------------------------- | --------------------- |
| `facing`     | 方块状态里的朝向，**指向输入侧**                        | north/south/east/west |
| rear         | 后方输入（`pos.relative(facing)`）              | 整数，可 >15              |
| front        | 输出侧（`pos.relative(facing.getOpposite())`） | 整数，可 >15              |
| left / right | 两个侧输入                                     | 0~15                  |
| $s$          | 输出强度                                      | 整数，可 >15              |
| $i$          | 间隔方块的充能等级                                 | 整数，可 >15              |
| $n$          | 被读容器的槽数                                   | 1~54                  |

## 一、朝向：`facing` 是输入侧，不是输出侧

这是最容易搞错的一处，因为它和“视觉上的箭头”是反的。

$$\boxed{\ \text{rear}=pos.\text{relative}(facing),\qquad \text{front}=pos.\text{relative}(facing.\text{getOpposite}())\ }$$

- Wiki 对 `facing` 的原话是：**从输出侧指向输入侧的方向**（the direction from the output side to the input side）。
- 外观上，比较器**前面只有一个火把**、后面有两个；**前面的箭头指的是输出**，也就是说**视觉箭头 = `front` = 输入的反方向**。
- 放置时比较器**背对玩家**。

> **中文社区的术语在这里是分裂的**：
> 中文 Wiki《红石电路》说“中继器、比较器的**指向**就是输出端所朝向的方块”（指视觉箭头）；
> TechMC 用“**前面**”表示输入侧。
> **两种说法都有人用，所以读别人的图时不要看“前后”，只看 `facing` 的坐标。**

坐标约定按 MC：`north = −Z`、`south = +Z`、`east = +X`、`west = −X`。
比较器在 $(x,y,z)$、`facing = north` → 读 $(x,y,z-1)$，输出到 $(x,y,z+1)$。

## 二、两种模式

比较器的模式由**前端火把亮不亮**决定（亮 = 减法）。

**比较模式**（火把熄灭）：

$$s=\begin{cases}\text{rear},& \text{left}\le\text{rear}\ \text{且}\ \text{right}\le\text{rear}\\ 0,&\text{否则}\end{cases}$$

**减法模式**（火把点亮）：

$$s=\max\bigl(\text{rear}-\max(\text{left},\text{right}),\ 0\bigr)$$

**判负是严格的 `>`。** 依据是“若任一侧面输入大于后方输入，则比较器关闭输出”：
所以 `rear == side` 时，比较模式照常输出 rear，减法模式输出 0。

**没有侧输入时**（两侧都是 0）：两个模式都输出 rear——比较器和中继器一样“原样传递”。

> 这两条是弱模电路里最常见的用法，但**同一个公式对强模也成立**：
> 我们把 rear 设成上千的值，减法模式就在做大数相减。一期的减法链、三期的比较器环都是这么用的。

## 三、时间

- 信号穿过比较器需要 **2 游戏刻（1 红石刻）**，侧输入同样 2 游戏刻。
- 比较器在计划刻执行前**先检查自己的通电状态**，所以它**通常不响应 1 刻的脉冲**
  （从侧面看恒为关，从后面看恒为开）。
- 例外：两个独立的观察者脉冲同时打到一个输入上时，它能响应 2 游戏刻的脉冲。

$$\text{1 红石刻（rt）}=2\ \text{游戏刻（gt)}=0.1\ \text{s}$$

---

## 四、侧输入只认少数几种来源

$$\text{侧输入}\in\{\text{红石粉、红石块、中继器、其他比较器、侦测器（特定情形）}\}$$

- **火把、按钮、拉杆不给“侧输入”**——它们给的是“充能”，这是另一套机制。
- **普通实心方块作侧输入恒为 0**（源码 `getControlInputSignal` 对实心方块返回 0）。
- 侧输入取 $\max(\text{left},\text{right})$，**不是相加**。

## 五、读容器

### 5.1 公式

$$\boxed{\ s=\begin{cases}0,& \text{容器为空}\\[2pt] 1+\Bigl\lfloor \dfrac{14}{n}\sum_{j}\dfrac{\text{count}_j}{\text{maxStack}_j}\Bigr\rfloor,&\text{否则}\end{cases}\ }$$

即“**各槽满度的平均值 × 14 向下取整，再 +1**”。
把“满度”乘 64 就是我们的折算单位 $U$：$\text{满度}_j=U_j/64$，两种写法完全等价
（推导与取值表见 `容器信号.md`，这里不重复）。

| 容器 | 槽数 $n$ |
|---|---:|
| 饰纹陶罐 | 1 |
| 熔炉 / 高炉 / 烟熏炉 | 3 |
| 漏斗 / 酿造台 / 漏斗矿车 | 5 |
| 投掷器 / 发射器 | 9 |
| 箱子 / 木桶 / 潜影盒 / 上锁箱 | 27 |
| 大箱子（双箱，按整体算） | 54 |

### 5.2 隔方块读容器

比较器正后方如果没有容器，它可以**隔着一个方块**去读后面的容器。源码（1.21.1）：

```java
int resultSignal = super.getInputSignal(level, pos, state);   // 间隔方块的充能
Direction direction = state.getValue(FACING);
BlockPos targetPos = pos.relative(direction);
BlockState targetState = level.getBlockState(targetPos);
if (targetState.hasAnalogOutputSignal()) {                    // ① 正后方就是容器
    resultSignal = targetState.getAnalogOutputSignal(level, targetPos, direction.getOpposite());
} else if (resultSignal < 15 && targetState.isRedstoneConductor(level, targetPos)) {  // ② 隔方块
    BlockPos blockPos = targetPos.relative(direction);
    BlockState blockState2 = level.getBlockState(blockPos);
    if (blockState2.hasAnalogOutputSignal()) {
        resultSignal = blockState2.getAnalogOutputSignal(level, blockPos, direction.getOpposite());
    }
}
```

读出来是三条规则：

1. **正后方就是容器** → 无条件读容器，容器优先。
2. **正后方是可传导方块、容器在它后面** → 只有该方块充能 $i<15$ 时才读容器。
3. **$i\ge15$ 就跳过容器**，直接把 $i$ 当输出。**强模也走这条**：$i=897$ 时输出 897。

$$\boxed{\ \text{门槛是 }i<15\text{，不是 }i=15\text{：任何 }\ge15\text{ 的充能都会压过容器}\ }$$

Wiki 的措辞是 “powered to signal strength 15”，很容易读成“只有恰好 15”。**源码是 `< 15`。**

### 5.3 一个方块被多处充能时，读哪一路

原版 `SignalGetter#getDirectSignalTo` 的语义不是求最大，而是**按固定顺序扫描、累加到 ≥15 就返回**：

```
running = 0
for dir in [DOWN, UP, NORTH, SOUTH, WEST, EAST]:     # 就是 Direction.values() 的顺序
    if 该方向有信号源向本方块发强充能:
        running = max(running, 它的值)
        if running >= 15:  return running            # ← 提前返回，后面的方向不再看
return running
```

两个直接后果：

| 情形 | 方块充能 |
|---|---|
| 只被一个强模比较器（如 3500）充能 | **3500**（原值穿过，不截断） |
| 被 **点燃的火把（15）** 与**前方的强模比较器（829）**同时充能 | **15**（火把在 DOWN，排第一，15 直接返回） |

**`DOWN` 排第一位，这就是“正下方的火把能遮蔽任何方向的更强充能”的原因。**

## 六、还能读什么

比较器不只读容器。它读的是“有模拟输出的方块”，除容器外还有一大批**方块状态**：

蜂巢（蜜量 0~5）、蛋糕（每片 2，满 14）、炼药锅（0~3）、雕纹书架（1~6）、堆肥桶（0~8）、
铜灯（亮 15）、铜傀儡雕像（1~4）、**命令方块（success count，可到 int 上限）**、
末地传送门框架（有眼 15）、物品展示框（1~8，转 45° 加 1）、唱片机（1~15）、
讲台（按页码）、重生锚（0/3/7/11/15）、幽匿感测体、潜影盒。

易错点：

1. **箱子/上锁箱上方有导体方块、或上面坐着猫** → 打不开 → 比较器**恒输出 0**，与内容物无关。
2. **展示框与容器占同一格**（比如展示框贴在箱子上）→ 输出**两者中较大的**。
3. **命令方块**是唯一能让比较器输出到 int 上限的方块——这也是“不写 NBT 也能拿到强模”的唯一路径。

## 判据与反例

1. **别用“前后”描述朝向。** 视觉箭头是输出，`facing` 是输入，两者相反。看 `facing` 的坐标，不看箭头。
2. **别把“≥15”写成“=15”。** 源码是 `< 15` 才读容器；15、897、任何 ≥15 的值都会压过容器。
3. **别说“多充能取最大”。** 是扫描顺序 + 累加到 ≥15 立即返回。正下方（DOWN）的火把有最高优先级。
4. **侧输入不是“所有元件都能给”。** 只认红石粉/红石块/中继器/比较器/侦测器；实心方块给 0。
5. **相等不算“侧输入更大”。** `rear == side` 时比较模式照常输出，减法模式输出 0。
6. **大箱子按 54 格整体算**，不是只算背后那一半。这条在算槽数 $n$ 时最容易错。
