## 一、强模 LUT 是怎么把整数变成容器权重的

### 1.1 单元结构

一个 LUT 单元 = **16 个容器**（$k=0..15$），一个对应一个输入电平。
输入 $x\in[0,15]$ 时：

$$c_k(x)=\begin{cases}b_k,& k\le x\\ a_k(x),& k\ge x+1\end{cases}
\qquad\text{（截断信号 }a_k\ge15\text{ 时接管）}$$

$$S(x)=\sum_{k=0}^{15}c_k(x),\qquad \lambda(x)=B-S(x)$$

### 1.2 核心公式：每个容器控制一个步长

$$\boxed{\ \Delta\lambda(x)=15-b_{x+1}\ }\quad\text{（红石粉截断）}$$

$$\Delta\lambda(x)=(29-x)-b_{x+1}\quad\text{（比较器截断）}$$

**改 $b_{x+1}$ 只改第 $x$ 个步长，其余 14 个不动。这就是"查找表"三个字的数学含义。**

反解：

$$b_{x+1}=15-\Delta f(x)$$

### 1.3 882 是从哪来的

$$b\in[0,\ 897]\quad\Longrightarrow\quad\Delta\lambda\in[15-897,\ 15-0]=[-882,\ +15]$$

$$\boxed{\ 882=897-15\ }$$

**这是步长窗口的下界，也就是本阶段一直用的"单容器上限 882"的真正出处。** 顺式管一个方向、反式管另一个方向，两者窗口互为镜像。

### 1.4 $\lambda$ 的上限不是 897

$$\lambda\ \text{是 16 个容器之和}\quad\Longrightarrow\quad\lambda_{\max}=15\times897=13\,455$$

**一个 $\lambda$ 由 16 个容器拼出来，897 只约束单个容器。** 这是我自己犯过的错，记在这里。

## 二、容器信号强度与物品数量

### 2.1 反推出的公式

桶 27 格。把**最大堆叠 1** 的物品（木斧）超叠到 `count:64` 塞进一格，
该格贡献 **64 个填充单位**；红石最大堆叠 64，一格贡献 `count/64` 个单位。

$$\text{fill}=64A+R\qquad(A=\text{斧总数},\ R=\text{红石数})$$

$$\boxed{\ \text{signal}=\begin{cases}0,&\text{fill}=0\\ 1+\bigl\lfloor 14\cdot\text{fill}/1728\bigr\rfloor,&\text{fill}>0\end{cases}\ }$$

用 `datapack/tiny_cnn/data/vessel/function` 里**现有的 512 个文件**逐个核对：

$$\boxed{\textbf{512 个文件，0 个不符}}$$

### 2.2 上限 897 的真正来源

$$27\ \text{格}\times 64=1728\ \text{填充单位}$$
$$\text{signal}=1+\frac{14\times1728}{27}=1+896=\mathbf{897}$$

**897 不是"桶能装 1728 个物品"，而是"每格能塞 64 个叠 1 的物品，27 格共 1728 个格当量"。**

### 2.3 调色板扩展到 0..897

现有调色板只到 **511**（16 格斧）。本阶段要 882，必须扩。

`src/barrel_palette.py` 已生成全部 **898 个**（0..897），每个都用 ≤27 格：

| signal | fill | 用格 |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 1 | 1 |
| 15 | 1728 | 1 |
| 100 | 12220 | 4 |
| 255 | 31351 | 9 |
| 511 | 62949 | 17 |
| 700 | 86277 | 23 |
| **882** | **108800** | **27** |
| 897 | 110592 | 27 |

**882 与 897 都在 27 格内可达。**

> 生成的坑：865..896 段若固定取"最小 fill"，余数 $R>0$ 会多占一格 → 28 格越界。
> 正确做法是在可行 fill 区间里搜一个 $(A,R)$ 使 $\lceil A/64\rceil+[R>0]\le27$。

## 三、数据包是怎么组织的

### 3.1 两层结构

```
datapack/tiny_cnn/data/
├── vessel/function/
│     barrel_0.mcfunction .. barrel_511.mcfunction     ← 调色板，一个信号一个文件
└── deploy_weights/function/
      deploy_all_layers.mcfunction                     ← 放置函数，一行一个容器
```

**调色板**（一个文件一行）：

```
setblock ~ ~ ~ minecraft:barrel{Items:[{Slot:0b,count:64b,id:"minecraft:wooden_axe"},…],
  CustomName:'"signal: 100, item: 12220"'}
```

**放置函数**（一行一个容器）：

```
execute at @s positioned ~-1 ~-1 ~0 run function vessel:barrel_100
```

$$\boxed{\text{参数}\ \longrightarrow\ \text{信号强度}\ \longrightarrow\ \text{调色板索引}\ \longrightarrow\ \texttt{setblock}}$$

**这个"调色板 + 定位调用"的分工是本阶段要直接复用的骨架。** 它把 NBT 细节锁在 898 个文件里，放置函数只需要坐标和信号值。

### 3.2 坐标是参数化算出来的

`gen_deploy_v3.py` 里的模式：

```python
ORDER = [13,14,11,12,9,10,7,8,5,6,3,4,1,2,0]     # 行 → z 的顺序
Z[r]  = 相邻差 2，唯 (2,0) 之间差 4
x_of(row,col) = (-1 if row%2 else 0) - 2*(14-col)
y     = 每层固定
```

然后

```python
for col in range(14,-1,-1):
    sig = cvals[row*15+col]
    lines.append(f"execute at @s positioned {x_of(row,col)} {Y} {Z[row]} "
                 f"run function vessel:barrel_{sig}")
```

**坐标映射同时存成 JSON**（`vessel_coords.json`），供后续引用。

### 3.3 参数 → 信号的编码

一期用 LUT 的步长公式：

$$c=\begin{cases}15-W,&\text{偶数层（顺式）}\\ 15+W,&\text{奇数层（反式）}\end{cases}$$

**奇偶层交替，就是为了让顺式和反式各管一个符号方向。** 这直接对应一期的 LUT 步长窗口两侧不对称。

### 4.1 第 2 块的关键问题

本阶段的位权重 $W^{(k)}_{i,j}$ 有正有负、范围 $[-882,+1764]$。而容器只能存 $[0,897]$（信号）。

可能的对应方式（待定）：

| 量 | 容器 | 说明 |
|---|---|---|
| $|W^{(k)}_{i,j}|$ | 一个容器 | 幅值直接进桶 |
| 符号 | 由"位取值"或"顺式/反式"承担 | 负权重要么把 $X^{(k)}$ 取反，要么换成下降阶梯 |
| $C_{i,\min}$、$P_i$、$c_i$、$T_i$ | 各自的容器或固定常数 | 一期的 $G_{i,0}$、$F_0$ 就是这类偏置容器 |

**一期的 $G_{i,0}$ 支线偏置 + $F_0$ 总线偏置，就是本阶段 $C_{i,\min}$ / $P_i$ 的对应物。** 这部分结构可以直接借鉴。

### 4.2 常数清单（来自编译器）

| 常数 | 个数 | 性质 |
|---|---:|---|
| $U^{(k)}_{j,i}$ | 2,048 | 整数，可负，$\lvert\cdot\rvert\le1764$ |
| $V^{(k)}_{p,j}$ | 16,384 | 同上 |
| $A_j$、$c_j$ | 64 + 64 | 非负整数 |
| $B_p$ | 32 | 非负整数 |
| $\beta$、$15\beta$ | 2 | 实数 / 整数 |

**容器总数 ≈ 18,600 个。** 调色板 + 放置函数的规模会比一期（2,340 个）大 8 倍。
