## 三、你的怀疑被证实：旧奖励模型就是个"类二次元探测器"

用旧的 优/良 奖励模型（274 条旧标签拟合）给这 153 张打分：

| 类别 | 旧奖励平均分 |
|---|---:|
| **类二次元** | **1.801** |
| 中 | 1.410 |
| 差 | 1.396 |
| 类三次元 | 1.296 |
| 类游戏 | 1.288 |

**类二次元 vs 其他可接受风格：+0.510，t = 11.20，p < 0.0001。**

**更严重的是**：**中（1.410）和差（1.396）的分数竟然高于类游戏（1.288）和类三次元（1.296）。**

所以旧奖励模型**根本没在区分"可接受 / 要避免"**——它只有一条轴：**像不像二次元**。

**这意味着之前所有纯化数字（58.8% → 90.2%）都要改写：它们优化的是"更像二次元"，不是"更可接受"。**

## 四、线性模型是错的工具

153 条风格标签上做 5 折交叉验证：

| 模型 | cv AUC |
|---|---:|
| **线性** | **0.543**（≈ 随机） |
| 二次特征（14 维） | **0.683** |
| kNN(25) | 0.664 |
| 4-16-1 小网络 | **0.690** |

**关系是非线性的。** 线性模型 +0.15 的差距，说明"可接受性"不是四个旋钮的线性函数。

这也解释了为什么旧奖励（线性）在旧任务上 AUC 0.79 却在旧任务上有效：**旧的"优/良"恰好接近线性（干净度 ∝ 低 |PC1|），而"可接受/避免"不是。**

### 用二次模型纯化（cv AUC 0.683）

| 保留 | n | 可接受率 | 95% CI | 提升 |
|---|---:|---:|---|---:|
| 不筛 | 153 | 67.3% | [59.5, 74.2] | — |
| 70% | 107 | 73.8% | [64.8, 81.2] | +6.5 |

| 25% | 38 | 92.1% | [79.2, 97.3] | +24.8 |

**保留 35% 的构成**：

| 类别 | 占比 |
|---|---:|
| 类二次元 | 64.2% |
| 类游戏 | 17.0% |
| 类三次元 | 7.5% |
| 中 | 9.4% |

**中/差 从 32.7% 压到 11.3%，而且三种风格都还在。** 这是真正对准你目标的纯化。

## 五、彩色可行性：明度推断不出颜色

### 数据
- 923,975 张 RGB 脸，过滤对称后 **321,219 张**，与明度数据**逐行完全对齐**（已校验）
- 饱和度 S 均值 0.320；**36.6% 的像素基本是灰的**（chroma < 0.05）

### 核心测量：能否从明度图推断颜色？

| 通道 | 线性读出 R² |
|---|---:|
| 饱和度 S | **0.073** |
| 色度 (max−min) | 0.110 |
| 色相 sin | 0.087 |
| 色相 cos | 0.037 |
| **色相（sin+cos）** | **0.062** |

**明度对颜色几乎零信息量。**

**结论：你设想的"拿明度图作为输入，训练饱和度和色相"这条路走不通。** 颜色必须有自己的条件输入。

### 但颜色本身是低秩的

| 主成分数 | 解释的颜色方差 |
|---:|---:|
| 4 | 65.7% |
| **8** | **75.1%** |
| 16 | 84.3% |
| 22 | 88.6% |
| 32 | 93.2% |

**颜色只需要 8~16 个数字就能解释大部分变化。**

### 因此彩色方案应该是

$$\underbrace{4\text{ 个明度 PCA}}_{\text{已有}} + \underbrace{8\sim16\text{ 个颜色 PCA}}_{\text{新增}} \;\to\; \text{明度}(32) + S(32) + H(32)$$

**输入从 4 个增加到 12~20 个**，而不是"零成本地从明度推出颜色"。
