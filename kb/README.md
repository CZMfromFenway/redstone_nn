# redstone_nn 知识库

**这不是文档库。** 文档回答"当时我们怎么想的"，知识库回答"现在什么是真的"。

一篇文档可以写几万字、里面一半是错的；**一页知识库只能有一个状态**，错的部分已经不在里面了。

---

## 怎么用（给人和 agent 都一样）

1. **动手前**：先读 `00_入口/状态与口径.md`，再按主题读对应的那一页。
2. **写作前**：先查 `00_入口/冲突登记表.md`，确认你要写的东西不是一条 open 的 C-xx。
3. **引用时**：只用"定案"页的结论；"待验"页引用时必须带状态。
4. **发现矛盾**：不要就地调和，**开一条 C-xx**，两边都写，等作者裁定。

## 每页的硬格式

```markdown
# <构件名>
状态: 定案 | 待验 | 已废 | 外部
可信度: 实机实测 / 数值验证 / 推导 / 口述
最后核实: YYYY-MM-DD · 谁
适用: <一句话写清边界，越窄越好>

## 结论
（只写今天仍然成立的东西，公式优先）

## 判据与反例
（能被什么推翻；我们曾被什么骗过）

## 证据
（原始文档 + 行号；脚本路径）

## 遗留
（未解决的，指向 C-xx 或"待验"）
```

**四段齐全 + 三个字段齐全，才允许标 `定案`。** 缺一段就只能是 `待验`。

---

## 状态的含义

| 状态 | 含义 | 能不能直接引用 |
|---|---|---|
| `定案` | 作者审阅过，且满足上面四条判据 | 能 |
| `待验` | 有依据但没走完验证，或有 open 的 C-xx 指向它 | 引用时必须带"待验" |
| `已废` | 被更晚的结论取代 | 不能，只能用来理解历史 |
| `外部` | 来自 hjkv 等，未经作者审阅 | 只能当线索 |

---

## 与旧文档的关系

- **旧文档不搬、不改名**，它们是证据层，知识库是结论层。
- 每页 `## 证据` 必须指到具体文档的具体行；指不到就不许写。
- 被推翻的结论不删，移到 `99_档案/`，并在原地留一行指针。
