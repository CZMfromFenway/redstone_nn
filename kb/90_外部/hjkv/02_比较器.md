# 比较器（Redstone Comparator）完整规则

> 来源：Minecraft Wiki「Redstone Comparator」条目（本机镜像 `Redstone Comparator.txt`，674 行）+ 反编译源码 + TechMC
> 本篇是**权威规则表**，写仿真器/做实验前先查这里，不要盲试。

---

## 1. 几何与朝向（最容易搞错的部分）

**[Wiki]** 方块状态 `facing` 的定义（原文）：

> **The direction from the *output* side to the *input* side of the comparator**,
> or the opposite from the direction the player faces while placing the comparator.

即 **`facing` = 从输出侧指向输入侧的方向**。

- **输入（rear）= `pos.relative(facing)`**
- **输出（front）= `pos.relative(facing.getOpposite())`**

**[Wiki]** 外观：比较器有**前面（front，单火把）和后面（back，两火把）**。
"the arrow on the top of the comparator points to the front"，**front 是输出**。
放置时比较器**背对玩家**（"faces away from the player"）。

> ⚠ **中文社区术语冲突**：
> - 中文 Wiki《红石电路》说"中继器、比较器的**指向**就是输出端所朝向的方块"（指视觉箭头）。
> - TechMC 用"**前面**"表示输入侧（"比较器总共有 3 个输入端，分别为前面和两个侧面输入"）。
> - NBT 的 `facing` 属性 = **输入侧**方向（MCHPRS 文档 §7 也这么写：比较器 facing 是"输入来向"）。
>
> **结论**：`facing` 属性 = 输入侧；视觉箭头 = 输出侧 = `facing` 的反方向。**以源码 `pos.relative(facing)` 为准。**

### 1.1 坐标速查（MC 方向）

`north = -Z`，`south = +Z`，`east = +X`，`west = -X`。

例：比较器在 `(x,y,z)`、`facing=north` → 读 `(x,y,z-1)`（北），输出到 `(x,y,z+1)`（南）。

## 2. 运算规则 **[Wiki]**

设 `rear` = 后面输入，`left`/`right` = 两侧输入。

**比较模式（front 火把熄灭）**
```
output = rear  if (left <= rear AND right <= rear)
output = 0     otherwise
```
> "If either side input is greater than the rear input, the comparator output turns off."

**减法模式（front 火把点亮）**
```
output = max(rear - max(left, right), 0)
```
> Wiki 例子：左 6、右 7、后 4 → max(4-7,0)=0；
> 左 5、右 2、后 9 → max(9-5,0)=4。

**[TechMC]** 同义表述：
- 比较模式：「取左、右输入的最大值，若其最大值**大于**前端输入，则不输出，否则输出前端输入。」
- 减法模式：「取左、右最大值，若其最大值**大于**前端输入，则不输出，否则输出（前端输入 − 侧面最大值）。」

**关键细节**：判定是 **strictly greater**（`>`），相等时正常输出。
所以 `rear == side` 时：比较模式输出 rear，减法模式输出 0。

**无侧面输入时**：无论哪个模式，都输出 rear（维持信号强度）。

## 3. 延迟与采样时机 **[Wiki]**

- 信号穿过比较器需要 **2 game tick（1 redstone tick）**。侧面输入同样 2gt。
- **比较器在执行计划刻前先检查自己的通电状态** →
  **比较器通常不响应 1-tick 的信号波动**（例如 1-时钟输入，从侧面看恒为关，从后面看恒为开）。
  例外：两个独立观察者脉冲同时打到一个输入上，比较器能响应 2-game-tick 脉冲。

## 4. 侧输入的来源限制 **[Wiki]**

> Side inputs are accepted only from **redstone dust, block of redstone, redstone repeaters, other comparators, and observers in specific scenarios**.

**比较器的侧面输入只接受这些**（不含火把/按钮/拉杆直接给侧输入——它们给的是"充能"而非"侧输入"）。

## 5. 测量方块状态（容器等）

### 5.1 容器信号强度公式 **[Wiki]**（与 **[源码]** 一致）

```
signal = floor(1 + (Σ 各槽满度 ÷ 槽数) × 14)      （容器非空时）
signal = 0                                          （容器为空时）
满度(槽) = 物品数 ÷ 该物品的堆叠上限
```

**[TechMC]** 等价表述：「输出信号强度 = 对每个物品槽位填充比例的平均值 × 14 向下取整，如果容器不是空的，再 +1。」

**Full-Stack-Equivalent（FSE）**：把 64 堆叠物品的 1 个记作 1 FSE。于是
- 堆叠上限 64 的物品：每件 **+1** FSE
- 堆叠上限 16 的物品（雪球/末影珍珠/告示牌…）：每件 **+4** FSE
- **不可堆叠物品（剑/斧/矿车…）：每件 +64** FSE

> 换算关系：`FSE = Σ(count_i / maxStackSize_i)`，而 `count_i / maxStackSize_i` 正是"满度"。
> **不可堆叠物品的堆叠上限是 1，所以 64 把剑 = 64 满度 = 64 FSE/件 × 64 件。**

### 5.2 各容器槽位数 **[Wiki]**

| 容器 | 槽数 | 满容器所需物品 |
|---|---|---|
| 装饰陶罐 | 1 | 1 |
| 熔炉/高炉/烟熏炉 | 3 | 3×64 |
| 漏斗/酿造台/漏斗矿车 | 5 | 5×64 |
| 投掷器/发射器 | 9 | 9×64 |
| 箱子/木桶/潜影盒/上锁箱 | 27 | 27×64 |
| 大箱子（双箱） | **54**（按整体计算） | 54×64 |

**反解公式** **[Wiki]**：
```
items required = max(目标强度, ceil(槽数 × 64 ÷ 14 × (目标强度 − 1)))
```

### 5.3 隔方块读容器 **[Wiki]**

- 比较器可以**隔一个"可传导红石信号的方块"**测量容器。
- **"The comparator disregards the power level of the intervening block in this configuration."**
- **但 Java 版例外**：若**间隔方块被充能到强度 15**，比较器输出 15，**无视容器满度**。
  （Wiki 引用 MC-64394："Comparators prefer containers through blocks, except when block power level is 15"）
  **基岩版无此例外。**
- 判定阈值是 **恰好 15**（不是 ≥15）。

### 5.4 其他可测方块 **[Wiki]**

蜂巢/蜂巢（蜜量 0–5）、蛋糕（每片 2，满 14）、炼药锅（0–3）、雕纹书架（1–6）、堆肥桶（0–8，7 级不稳定会变 8）、
铜灯（亮 15）、铜傀儡雕像（1–4）、**命令方块（success count，可到 int 上限）**、 crafting 方块（crafting table）、
末地传送门框架（有末影之眼 15）、物品展示框（1–8，转 45° 加 1）、唱片机（唱片对应 1–15）、
讲台（`floor(1 + (页码-1)/(总页数-1) × 14)`，单页书恒 15）、重生锚（0/3/7/11/15）、
幽匿感测体、潜影盒（可测量，即使打不开）、唱片机。

**注意**：箱子/上锁箱**上方有导体方块或坐着猫**时无法打开 → 比较器输出恒为 **0**（无论里面有多少东西）。

### 5.5 展示框与容器同位 **[Wiki]**
物品展示框与箱子/讲台/酿造台等占同一格时，比较器输出**两者中较大的**。

## 6. 其他

- 比较器**不发出红石粒子**（MC-51692）。
- 比较器实体：`OutputSignal` 是 **int**（不是 byte），无原版截断。
- 侧输入取 `max(left, right)`，不是相加。
- 比较器读取大箱子时按 **54 格整体**计算，不是只算背后那一半。
- 比较器可以放在玻璃/冰/荧石/海晶灯上（19w12b 起）。

## 7. ★ 隔方块读容器的优先级规则（强模关键，已实测核验）

### 原版源码（`ComparatorBlock.getInputSignal`，1.21.1）
```java
int resultSignal = super.getInputSignal(level, pos, state);   // 间隔方块的充能等级
Direction direction = state.getValue(FACING);
BlockPos targetPos = pos.relative(direction);
BlockState targetState = level.getBlockState(targetPos);
if (targetState.hasAnalogOutputSignal()) {
    resultSignal = targetState.getAnalogOutputSignal(level, targetPos, direction.getOpposite());
} else if (resultSignal < 15 && targetState.isRedstoneConductor(level, targetPos)) {
    BlockPos blockPos = targetPos.relative(direction);
    BlockState blockState2 = level.getBlockState(blockPos);
    if (blockState2.hasAnalogOutputSignal()) {
        resultSignal = blockState2.getAnalogOutputSignal(level, blockPos, direction.getOpposite());
    }
}
return resultSignal;
```

### 规则
1. 比较器**正后方**就是容器（无间隔）→ **无条件**用容器的模拟输出，容器的值优先。
2. 比较器正后方是**实心块**、容器在实心块再往后一格 → **只有当实心块的充能等级 `< 15` 时**才去读容器。
3. **判定是严格小于 `< 15`**（不是 `<= 15`），所以**充能等级 > 15（强模）时同样会跳过容器**，
   直接采用充能值本身。
   → **强模下这条规则不变，只是"压过容器的门槛"从 15 变成了"任何 ≥15 的值"。**
4. Wiki 的措辞是 "powered to signal strength 15"，容易被误读成"只有恰好 15"。
   源码是 `< 15`，所以 **>15 一样压过容器**。**（此点由用户提出，已在 mchprs 强模式下端到端实测证实）**

### 实测（mchprs 强模模式，`tests/strong_mode.rs`）
电路：`桶(读数 N) → 比较器A → 实心块 → 比较器B（隔方块读另一个桶 M）`

| 实心块充能 | 后方容器 | 比较器B 输出 | 含义 |
|---|---|---|---|
| 897 | 5 | **897** | >15 压过容器 ✓ |
| 15 | 9 | **15** | 恰好 15 也压过容器 ✓ |
| 5 | 9 | **9** | <15 时读容器 ✓ |

### mchprs 的两条路径都已实现这条规则
- 原生红石：`calculate_input_strength` → `else if base_input_strength < 15 && input_block.is_solid()`
- Redpiler：`get_all_input` 后 `if let Some(far_override) = far_input && input_power < 15`

### 附带确认：实心块充能**不衰减**
Redpiler 的边权重模型里，`get_redstone_links` 的实心块分支建边时**距离不递增**，
只有红石粉（`search_wire`）才累加距离 —— 与原版"方块充能等级原样传递"一致。
红石粉则每格 −1。
