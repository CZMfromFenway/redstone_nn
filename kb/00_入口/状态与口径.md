## 四、四期的范围（R-05 的推论）

**做**：彩色头像生成算法；离散/调色板/量化潜变量的比较；人的盲测；把结果做成可看的网页。

**不做**：schem 编译、容器可达性、误差预算、投掷器拟合、体积核算、红石布局。

**因此**：`40_编译/` 这一章在四期**不会被引用**，它是给三期收尾和五期用的。知识库仍然要建它，因为**它的证据已经齐了**，不建就会烂在文档里。

## 五、作者的取舍（判断“50_算法”各页时要记住）

> 我精通红石工程的程度深于我精通机器学习算法的程度。取舍是：不太在意具体方法，只要红石能实现就行；不太在意是否有更好的路径，只要当前路径达到满意就行。

后果：**算法侧的结论要按“够用”而不是“最优”来读**。作者自己写过“可能真的漏掉了极高效且适合红石的算法”。所以 `50_算法/` 的页面必须写清“这个结论是在多大范围内搜出来的”。

## 六、定案页的地位与更新规则（2026-10-30 定）

$$\boxed{\text{知识库里标 } \texttt{定案} \text{ 的内容，优先级最高}}$$

1. **高于一切**：高于旧文档、高于 agent 的总结、高于外部资料（包括 hjkv 的库）。有冲突时以定案页为准。
2. **不许自发修改**：agent 整理、写总结、做新实验时，**都不能改定案页**。发现定案页有问题，走两步：先开 `冲突登记表` 的 C-xx，再写一条更新提案。
3. **只有作者说“更新知识库”才改**：明确指示后，改正文 + **必须在 `更新记录.md` 追加一条**（改了什么 / 依据 / 影响）。
4. **升级与降级都要记录**：`待验 → 定案`、`定案 → 待验/已废` 都是状态变更，一律入更新记录。
5. **定案页出错时的处理**：不是悄悄改掉，而是保留旧结论到 `99_档案/`、写清“为什么当时成立、后来被什么推翻”、再在新版里指向它。

> 这条规则的用处：它把“我上次说过”和“现在成立”分开。四期做实验时会大量产出与旧结论冲突的结果，若允许随手改，知识库三个月就会重新变成一堆论文。
