# PCA-22 头像生成器 · 交互实验台

在浏览器里拖动 22 个参数，实时看生成出来的 8×8 头像。**页面里有五个模型可一键切换**，其中包含两个新架构（32 通道连续输出、16 色彩）。

## 怎么打开

浏览器出于安全原因**不允许 `file://` 页面读取本地 json**，所以必须用本地 http 服务：

```powershell
node src\serve_webapp.js webapp 8770
```

然后打开 <http://127.0.0.1:8770/>

打标工具：<http://127.0.0.1:8770/label.html>

## 五个模型

| 按钮 | 文件 | 结构 | 输出 | 逐像素准确率 | 相邻同色率 |
|---|---|---|---|---:|---:|
| **λ=5 · 20000步 · 灰度最佳** | `pca22_lam5_model.json` | 22→256→256→512 | 32×16 灰度 logits | **0.7005** | **60.7%** |
| 无噪声 · 6000步 | `pca22_nonoise_model.json` | 同上 | 同上 | 0.6429 | 50.3% |
| 有噪声 · 1500步 | `pca22_model.json` | 22+64→…→512 | 同上 | 0.4779 | 48.6% |
| **32通道连续 · 参数少61%** | `pca22_gray32_model.json` | 22→256→256→**32** | **32 个连续明度** | **0.7594** | 51.7% |
| **16色彩 · 512输出** | `pca22_color16_model.json` | 22→256→256→512 | 32×16 **调色板** logits | 0.6475 | 68.7% |

**切换模型时 22 个参数保持不变**，所以能直接看到同一组输入在不同架构下的差别。

参考值：灰度真实脸 **60.5% / 6.80 / 13.8**（相邻同色率 / 孤立像素 / 连通色块），彩色真实脸 **66.1% / 4.05 / 10.3**。

## 三种输出模式（页面自动识别）

页面从每个模型的 `meta.output_mode` 判断怎么解码：

| output_mode | 含义 | 渲染 |
|---|---|---|
| `logits_gray` | 32 位置 × 16 灰度级 logits | 取 argmax 得灰度级 0..15 |
| `logits_palette` | 32 位置 × 16 **调色板颜色** logits | 取 argmax 得调色板索引 → 映射到 RGB |
| `continuous32` | 32 个**连续**明度值（0..15） | 直接按连续值渲染（保留级间细节） |

**调色板索引是无序的 16 个类**，所以彩色任务比灰度难——它没有"明暗相邻"的结构可借。实测彩色准确率 0.6475，低于灰度的 0.7594。

**32 通道的连续值是真连续的**：在一张脸上只有 6/32 个通道落在整数附近（全样本约 39.5%），其余都携带级与级之间的信息。这正是 512 logits 表示不了的东西。

## 32 通道连续输出的意义

| | 512 输出（λ=5 灰度） | **32 通道连续** |
|---|---:|---:|
| 参数量 | 203,264 | **79,904（少 61%）** |
| 输出维度 | 512 | **32** |
| 逐像素准确率 | 0.7005 | **0.7594** |
| 平均绝对误差 | — | **0.315 级** |
| 相邻同色率 | **60.7%** | 51.7% |

**准确率更高、参数少 61%，但同样 λ=5 下平滑度不如 512**。说明**连续输出对同一个惩罚的响应更弱**，需要更大的 λ 才能达到同样的平滑度（正在验证 λ=15）。

## 页面能做什么

| 功能 | 说明 |
|---|---|
| **22 个滑块** | 每个是一个 PCA 主成分，单位是**标准差倍数**。0 = 数据集平均，±1 ≈ 常见范围，±3 ≈ 极端 |
| **🎲 随机采样** | 从标准正态里抽 22 个数 |
| **🖼 用真实脸当起点** | 随机挑一张真实脸，载入它**精确的** 22 个 PCA 值 |
| **⭘ 归零** | 全部设为 0 = 平均脸 |
| **🔄 重新采样** | 换噪声种子 |
| **温度** | <1 更保守，>1 更随机 |
| **按风格包裹采样** | 从你标注的类二次元/三次元/游戏样本拟合出的**高维正态**里采样 |
| **真实脸画廊** | 24 张留出集真实脸，点一张载入它的 22 个参数（五个模型共用同一批） |
| **三图对照** | 生成(采样) / 生成(取众数) / 真实参考 |
| **实时杂色指标** | 相邻同色率 / 孤立像素 / 连通色块 |

## 关于"取众数 vs 采样"

**这个模型应当用取众数（argmax），不要用采样。**

| 解码方式 | 相邻同色率 |
|---|---:|
| **取众数** | **60.7%**（≈真实脸 60.5%） |
| 采样 | 42.1% |
| 真实脸 | 60.5% |

原因经实测：16 路输出**几乎单峰**——严格单峰 62.3%、**宽松单峰 96.2%**、平均峰数 **1.05**、
最大概率均值 **0.631**。所以 argmax 是自然且正确的选择。

**这对红石是好消息**：只需 argmax（比较大小），**不需要随机源**。

## 已知局限（诚实说明）

1. **判别器整夜没被追上**（准确率稳在 0.91~0.92）。实测**去掉对抗项结果几乎不变**
   （0.6318 vs 0.6326），所以进步几乎全部来自交叉熵监督。
2. **采样版仍明显差于众数版**。TV 惩罚平滑了众数，但**没有让概率分布变尖**，
   所以采样仍从扁尾部抖动。
3. **风格聚类主要按明暗分层，不是按"二次元/三次元/游戏"**。与你标注的标签部分吻合
   （类二次元 90% 落入最亮的两簇），但**不是真正的风格维度**——这解释了为什么按风格
   分开训练全部失败。
4. **"改采样正态形状"（CEM）实测无效**：100 个标签后只提升 0.1 个百分点。
   有效的是**奖励模型 + 候选筛选**（+25 个百分点），见 `results/strategy/`。
