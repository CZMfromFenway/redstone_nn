# 4 -> 64 矩阵乘法器（强模）：测试案例说明

**交付对象**：hjkv（MCHPRS 强模支持）　　**文件**：`layer1_matmul_4to64_mc1.21_v1.schem`

**日期**：2026-10-25　　**来源**：redstone_nn 三期工程（把 4-64-32 量化网络编译成红石）的第 1 层

---

## 0. 一句话

这是一台**纯强模的 4 -> 64 矩阵乘法器**：输入是 4 个 0..255 的整数（共 32 个二进制位），
输出是 64 个比较器，每个给出该通道的累加量 **N**（整数，0 到约 11000）。

它只用到四种东西：比较器、木桶（存权重）、实心方块、火把。
**没有红石粉、没有中继器、没有活塞。**

### 4.1 调试用的检查点（头部不对时先看这些）

每个通道还有 4 个中间值，其中前两个**与输入完全无关**，所以第一次接线前就该能读到固定值：

| 位置 | 坐标 | 含义 |
|---|---|---|
| 灰环 K | `(1, 2ch+3, 21)` | K = ΣS（全部容器值之和），**与输入无关** |
| 白环 W0 | `(11, 2ch+3, 23)` | W0 = J·K − 15nb，**与输入无关** |
| 白总线 | `(11, 2ch+3, 21)` / `(…, 15)` / `(…, 9)` | 依次减掉四条链后的运行值 |
| 头部 | `(11, 2ch+3, 3)` | 最终 N |

正常关系：`W0` --减 d3--> `(11,y,21)` --减 d2--> `(11,y,15)` --减 d1--> `(11,y,9)` --减 d0--> `N`

> **最快的「板子没贴坏」检查**：先读 K 与 W0，它们不随输入变化（例如 ch0 的 K=9176、W0=36224）。

## 5. 输入整数 -> 32 个方块

```python
for i in range(4):            # 4 个输入
    for k in range(8):        # 每个 8 位
        bit = (X[i] >> k) & 1        # 第 k 位，k=0 是最低位
        if bit: 给坐标 (x[i][k], 0, z[i][k]) 充能
        else:   不充能
```

例：`X = (186, 37, 204, 91)`，其中 `X[2] = 204 = 0b11001100`：

```
204 = 1x128 + 1x64 + 0x32 + 0x16 + 1x8 + 1x4 + 0x2 + 0x1
=> 位 7,6,3,2 = 1  => 给 (i=2, k=7/6/3/2) 那 4 个方块充能，其余 4 个不动
```

---

## 6. 输出应该等于多少

```
N[ch] = sum over i=0..3, k=0..7 of ( W[ch][i][k] * bit_k(X[i]) - min(0, W[ch][i][k]) )
```

- `W[ch][i][k]`：该通道该输入该位的**整数位权重**，全部 2048 个值在 `weights_L1_b8.json` 里。
- 后一项 `min(0, W)` 是「负权重的偏置」，板上由火把亮灭自动完成，**你不需要管**。
- 每一项都减去 `min(0,W)`，所以 **N >= 0 恒成立**，最大约 11 000。

## 8. `predict.py`：自己算期望值

```bash
python predict.py 0 0 0 0             # 全 0
python predict.py 186 37 204 91       # 任意一组
python predict.py 186 37 204 91 --json
python predict.py --coords            # 只打印坐标表
```

输出包括：**哪些方块要充能**（带坐标）+ **每个通道的期望 OutputSignal**。
> 我们另有一个**板级仿真器**（能画出每一格、逐格求值、改任意输入）——如果 MCHPRS 那边需要，

纯 Python 3，无第三方依赖，只读同目录的 `weights_L1_b8.json` 与 `io_map.json`。

## 9. 已知限制 / 可能踩的坑

| # | 项 | 说明 |
|---:|---|---|
| 1 | 版本 | 1.21 -> 1.20.4 需手动转换（见 1.1） |
| 2 | 未跑全量 | 见 1.2 |
| 3 | 火把亮灭的「空闲态」 | 文件里烧录的亮灭按全 0 输入算。接上输入后由游戏重算；**若 MCHPRS 不重算火把状态，可能需要先 tick 一次** |
| 4 | 比较器 `powered` 与 `OutputSignal` | 文件里两者一致。**若转换工具只改 `OutputSignal` 而不同步 `powered`，环会失效**（我们在游戏里踩过） |
| 5 | 环 | 灰环 / 白环 / 配对区的 Sa 环都是「4 比较器 + 4 中介方块」的自锁环，靠烧录值启动。**若 MCHPRS 把 `OutputSignal` 当普通方块属性重算，需要保留环的初始值** |
| 6 | 时序 | 比较器每级 1 tick；128 层高的塔链延迟可观（未测），但稳态值不受影响 |
| 7 | 输入驱动 | 文件里**没有**总线。你需要自己给那 32 个方块充能；任何 >=1 的红石源都可以（亮火把 / 中继器 / 拉杆） |

## 11. 补充：另有一份「预减 P-1」的变体

我们另外导出了 `layer1_relu.schem`：白环整体减掉了 `P-1`，于是头部输出直接变成
`max(0, N-P+1)` —— 那是后端 RELU 除法器要的输入。

**本案例用的是普通版**（头部输出就是 N），因为它最好验证。
如果 MCHPRS 那边跑通了、想接着测输出级，再找我们要那一份。
