# 一次由我自己引入的数据对齐错误（已修复并加了门禁）

> 记录原因：这个错误差点让我把"**训练失败**"误判成"**低维模型塌陷**"。

---

## 一、现象

第一次跑 k=4 / k=8 时，指标是：

| 模型 | 准确率 | 同色率 |
|---|---:|---:|
| k=4 | 0.0525 | 79.9% |
| k=8 | 0.0519 | 78.1% |
| 参照 k=22 | — | — |

准确率 **0.0525** 低于随机水平 1/16 = 0.0625，而同色率 79.9% 却接近真实数据 77.6%。

**我当时的解读**：输出退化成固定脸（忽略输入）。

**这个解读是错的。**

---

## 二、真正的检验

我把**参照模型 s32_tv5** 放进同一套评估代码：

| 评估方式 | 准确率 |
|---|---:|
| 它自己报告 | 0.7594 |
| 我的评估代码给出 | **0.0621** |

**同一个权重、同一个数据，我的代码算出 0.06，它自己报 0.76。** 所以问题在我的**数据管道**，不在模型。

---

## 三、根因：是我为省内存做的"优化"

为了支持多进程并行训练，我原先写的这行代码每次会临时分配一个 `(923975, 8, 8, 16)` 的 float64 数组 = **7.05 GiB**：

```python
gyi = np.abs(gray[:, :, :, None] - LEVELS[None, None, None, :]).argmin(-1)
```

我把它换成了等价的解析式：

```python
gyi = np.clip(np.rint(gray / 17.0), 0, 15).astype(np.int64)   # ← 错了
```

**我以为两者等价。它们不等价。** 差别只在"正好落在两个等级中点"的情况：

| 灰度值 | `argmin` | `np.rint` |
|---|---:|---:|
| 8.5 | 0（首个最小值） | **0** |
| 25.5 | 1 | **2**（银行家舍入到偶数） |
| 246.5 | 14 | **14** |

实测：在 923,975 × 64 个元素里有 **594 个**不同，分布在 **127 行**上。

**后果是致命的**：这个量化结果被用来过滤对称脸。

| 版本 | 选出的对称行数 | 与 `L0_full_idx` 逐行一致 |
|---|---:|---|
| 原版广播 | **321,219** | **100%（全部 321,219 行相同）** |
| 我的 rint/17 | **321,221** | 25%（偏移 +2 处也只有 53%） |

多出 2 行后，**行序整体与目标数组错开**。于是条件向量描述的是 A 脸，目标却是 B 脸 ——
模型只能学条件均值，准确率跌到随机水平，输出是一张平滑的平均脸（所以同色率虚高）。

---

## 四、修复

正确的等价形式是**平局向下**：

```python
gyi = np.clip(np.ceil(gray / 17.0 - 0.5), 0, 15).astype(np.int64)
```

实测与 `argmin` 在全量数据上 **0 处差异**，且不再分配 7 GiB。

同时把训练脚本改成 **条件和目标都从 `L0_full_idx` 构建**，从结构上消除两套行序的可能。

---

## 五、加了门禁（这是比修复更重要的部分）

训练开始前，先做一次线性读出：

```
从 k 个 PCA 坐标线性回归到目标，看逐像素准确率
```

如果这个值低于 0.30，脚本**直接中止**并报错，不浪费一次训练。

现在的实测值：

| k | 线性读出准确率 | 随机水平 |
|---:|---:|---:|
| 4 | **0.3269** | 0.0625 |
| 8 | **0.4220** | 0.0625 |
| 22 | **0.7999** | 0.0625 |

**如果当初有这道门禁，这个错误会在 5 秒内被发现，而不是在跑完 40 分钟训练之后。**

---

## 六、影响范围（诚实说明）

**受影响**：只有我新写的 `dim_sweep.py` 那批 k=4/k=8 训练。全部作废，已重训。

**未受影响**：

- `sweep_condition.py`（PCA-1/2/4/8/16/22 那批早期模型）用的是**原版广播**，量化正确，
  所以之前报告的 acc 0.2104（PCA-4）等数字仍然有效
- `shrink_32out.py`（s32_tv5 参照模型）同样用原版广播，权重和它的自报指标都没问题

**仍受影响的工具**：`export_dims.py`、`progress_sheet_v2.py`、`pca_analysis.py`
都已被我改成错误的 `rint` 版本，现已修回 `ceil(x−0.5)`。这三个脚本只用于评估和绘图，
不产生权重，且 2 行差异对它们的输出没有实质影响，但公式已修正。

**一个额外收获**：k=4 的线性读出上限是 **0.3269**，k=8 是 **0.4220**。
这告诉了我们**理论上限**——如果神经网络能达到这个上限，那么"4 个输入生成合理随机头像"
就是可行的。
