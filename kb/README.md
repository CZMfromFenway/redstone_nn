# redstone_nn 知识库

**这不是文档库。** 文档回答“当时我们怎么想的”，知识库回答“现在什么是真的”。

一篇文档可以写几万字、里面一半是错的；**一页知识库只能有一个状态**，错的部分已经不在里面了。

---

## 三条铁律

1. **`定案` 页是最高优先级。** 它高于任何文档、任何我的总结、任何外部资料。有冲突时以 `定案` 页为准，**不许现场调和**。
2. **只有作者明确说“更新知识库”才改 `定案` 页。** 别人（包括 agent）只能提案，不能直接改。
3. **每一次改动都记进 `00_入口/更新记录.md`**：改了什么、为什么、谁批的。没有记录的改动视为无效。

---

## 怎么用（给人和 agent 都一样）

1. **动手前**：先读 `00_入口/状态与口径.md`，再按主题读对应的那一页。
2. **写作前**：先查 `00_入口/冲突登记表.md`，确认你要写的东西不是一条 open 的 C-xx。
3. **引用时**：只用“定案”页的结论；“待验”页引用时必须带状态。
4. **发现矛盾**：不调和，**开一条 C-xx**，两边都写，等作者裁定。
5. **想改定案页**：先写提案（改哪句、依据什么、影响谁），等作者点头。

## 每页的硬格式

```markdown
# <构件名>
状态: 定案 | 待验 | 已废 | 外部
可信度: 实机实测 / 数值验证 / 推导 / 口述
最后核实: YYYY-MM-DD · 谁
适用: <一句话写清边界，越窄越好>

## 符号
（本页出现的每个符号的含义与取值；不许让读者去猜）

## 结论
（今天仍然成立的东西，公式优先）

## 判据与反例
（能被什么推翻；我们曾被什么骗过）

## 遗留
（未解决的，指向 C-xx 或“待验”）
```

**四段齐全 + 四个字段齐全，才允许标 `定案`。** 缺一段就只能是 `待验`。

**不给“证据”段。** 理由：定案页本身就是最高权威，再指回旧文档反而会把旧文档里的错误带进来。
需要的可复现材料（脚本、计算）放在同目录的 `_calc/` 下，在正文里一句点出即可。

> 唯一保留的溯源：涉及**游戏机制**的页面，允许在正文里直接引 Minecraft Wiki 的条目名充当口径依据（那是外部权威，不是我们的旧文档）。

## 状态的含义

| 状态 | 含义 | 能不能直接引用 |
|---|---|---|
| `定案` | 作者审阅过，且满足四条判据 | 能，且**优先于一切** |
| `待验` | 有依据但没走完验证，或有 open 的 C-xx 指向它 | 引用时必须带“待验” |
| `已废` | 被更晚的结论取代 | 不能，只能用来理解历史 |
| `外部` | 来自 hjkv 等，未经作者审阅 | 只能当线索 |

## 与旧文档的关系

- **旧文档不搬、不改名**，它们是过程记录；知识库是结论层。
- 被推翻的结论不删，移到 `99_档案/`，并在旧文档顶部留一行指针。
- 旧文档说错的地方，**不在知识库里复述**；要么不提，要么按定案页的写法写。
