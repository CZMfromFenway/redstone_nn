## 与我们现有结论的关系

### 被它证实的

- **隔方块读容器的 ≥15 门槛**：与 `hjkv/02 §7` 的源码一致。**C-01 的这一半结案。**
- **897 = 1 + 14×64**：`hjkv/03 §4` 独立枚举得 898/898、864（缺口 804）、790（缺口 730），与我们的表逐格吻合。

### 被它修正的

- **“多充能取最大”不成立**。真实规则是**扫描顺序 + 累加到 ≥15 就返回**。
  这解释了作者 R-01/R-02 说的“比较器优先级并不低”：不是优先级问题，是**顺序 + 提前返回**。
  hjkv 的证据是 6730 个烧录值：按 max 算有 **1173 个不符**，按扫描算 **6730 个全对**。

### 已澄清的

- **C-23（26.x 容器读数异常）已结**：作者 2026-10-31 在 **26.2** 用
  `/data merge block -29 111 -112 {Items:[{count: 64, Slot:0, id:"minecraft:wooden_axe"}]}`
  写入单槽 64 把木斧，木桶输出 **>30**（按公式应为 34）。强模容器在 26.2 仍成立。
