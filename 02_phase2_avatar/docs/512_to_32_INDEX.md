## 一句话结论

**成本目标达成**：生成器的乘法从 202,240 降到 **1,728**（原来 0.85%），准确率仍有 0.679。
**质量目标未达成**：32 输出模型只有 26~29% 的值落在整数级上，其余停在级与级之间，
渲染成渐变 → 视觉上偏糊。根因是 **28.14% 的位置条件分布是多峰的**，
而单个连续值只能取平均。

## 试过并且失败的修法（不要再重复）

| 修法 | 为什么失败 |
|---|---|
| 连续场 TV 惩罚 | 惩罚差值大小，不惩罚"跨级"。6.49 与 6.51 差 0.02 但落在不同级 |
| 整数吸附惩罚 | MSE 已在推向整数目标，冗余。实测零效果 |
| 直通量化目标 | **直通估计器梯度与未量化相同**，只改前向不改梯度，数学空操作 |
| 四舍五入后场的 TV | 同上，受限于梯度没变 |
| 混合密度输出（2 个分量） | 承诺度提高到 51.2%，但准确率崩到 0.4782——"选哪个模式"的信息不在输出里 |

## 修掉的 bug

1. **网页假设网络固定 3 个线性层**，对 2 层网络会把最后一层应用两次
   （误差 88 个单位）。现在支持任意层数，8 个模型全部校验通过（最大误差 5.7e-6）。
2. **`fit_reward.py` 会把不同架构的标签混在一起训**。同一 22 维向量在不同架构下
   画出不同的脸，必须用 `--model <key>` 指定。
3. 导出脚本的权重布局搞反（转置），以及灰度级 0~15 被当像素值 0~255 渲染导致全黑。

## 下一步建议

**先验证"接受软化"是否可接受**：在游戏内实际缩放下看 32 输出模型，
如果糊的程度不明显，那就直接用 `w32`（1,728 次乘法），红石项目立刻变得可行。

**如果糊不可接受**，再考虑提高输入维度（让双峰位置变得可区分），
而不是继续在输出格式上想办法——这条路上的四种修法已经全部试过。
