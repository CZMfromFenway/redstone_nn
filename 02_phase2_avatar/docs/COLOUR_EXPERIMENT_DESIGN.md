# 彩色头像生成：实验设计

> 用户离场前的要求：把自己的灰度图和全彩图的 PCA 一起给网络，分两步生成——第一步用灰度 PCA 出灰度图，第二步用「灰度图 + 彩色 PCA」出颜色。
> 本文先固定设计，再执行。设计里每一处选择都写明理由，便于回来时逐条核对。

---

## 一、已知事实（前面实测的，不需要重做）

| 事实 | 数值 | 来源 |
|---|---|---|
| 对齐后的彩色样本 | **321,219 张** | `colour_feasibility.py`，与明度数据逐行一致 |
| 明度**单独**推断饱和度 | $R^2=0.071$ | 同上 |
| 明度**单独**推断色相 | $R^2=0.063$ | 同上 |
| 颜色 PCA 前 8 维解释方差 | 75.1% | 同上 |
| 颜色 PCA 前 16 维 | 86.2% | 同上 |
| 灰阶 32 + 颜色 4 维 → 色相 | $R^2=0.315$ | `colour_stage2.py`（线性读出）|
| 颜色 4 维单独 → 色相 | $R^2=0.182$ | 同上 |
| 基本是灰的像素比例 | **36.6%**（chroma<0.05）| 同上 |

**两条已确定的设计约束：**

1. **第二阶段必须收到彩色 PCA。** 只给灰度图，颜色预测不可行。
2. **灰度和彩色 PCA 有协同。** 颜色 4 维单独预测色相 0.182，加上灰阶跃升到 0.315。所以两路输入都要留。

**注意**：上面都是**线性读出**的下限。灰度那边我们见过线性 0.543 → 网络 0.690 的跃升，所以第二阶段值得训练真实网络，而不是停留在线性。

## 二、数据表示

### 2.1 颜色编码：RGB，每通道 4 bit

$$\text{RGB}_{4\text{bit}}=\mathrm{round}\!\left(\frac{\text{RGB}_{8\text{bit}}}{17}\right)\in[0,15]^3$$

**为什么用 RGB 而不是 HSV：**

| | RGB | HSV |
|---|---|---|
| 红石实现 | 三个通道各 4 bit，直接驱动三色灯/染色方块 | 需要角度运算（色相是 0~360°）|
| 损失函数 | 欧氏距离 | 色相是循环量，需要 sin/cos 编码 |
| 与灰度关系 | $Y=0.299R+0.587G+0.114B$，线性 | 非线性 |

**HSV 仍然要测量**（作为诊断指标），但不作为训练目标。色相误差用循环距离统计。

### 2.2 目标布局：32 个位置 × 3 通道 = 96 维

沿用灰度那条**完全相同的**布局约定：
$$\text{row}=p\bmod 8,\qquad \text{col}=\lfloor p/8\rfloor,\qquad \text{镜像到}\ 7-\text{col}$$

**镜像在颜色上是否成立？必须验证。** 灰度的镜像一致率是 80.9%（16 级）；颜色需要单独测——如果左右颜色差异很大，强制镜像会破坏数据。**这是设计里的第一个待验证点。**

### 2.3 输入

| 名称 | 维度 | 含义 |
|---|---|---|
| 灰度图 $G$ | 32 | 第一阶段产出的 0~15 灰度级，归一化到 [0,1] |
| 颜色 PCA $\text{cPC}_k$ | $k$ | 对 96 维 RGB（32 位置 × 3 通道）做 PCA 的前 $k$ 个分量，标准化 |

**颜色 PCA 是否包含灰度方向？** 我们的做法：**不人为剔除**，但在评估时测量"$k$ 个分量里有多少方差是灰度"，以便解释结果。用户说了两种都可以，我不做人为限制。

## 三、模型

### 3.1 方案 A（用户提出的两阶段）— 主方案

$$\text{阶段1：}\ \mathbb{R}^4\ \xrightarrow{4-256-256-32}\ 32\ \text{灰度级}\quad(\text{已训好，权重冻结})$$

$$\text{阶段2：}\ [G\ (32),\ \text{cPC}_k\ (k)]\ \xrightarrow{\ \text{MLP}\ }\ 96\ \text{个 RGB 值}\ (0..15)$$

阶段 1 的权重**完全冻结**，不参与彩色训练。这样彩色是"给已有灰度图上色"，与红石部署顺序一致（先把灰度做好，再加一层上色）。

### 3.2 方案 B（联合）— 对照

$$\mathbb{R}^{4+k}\ \xrightarrow{\ \text{MLP}\ }\ 96\ \text{个 RGB 值}$$

一次出全部颜色，不用阶段 1。**对照作用**：检验"分两步"是否比"一步"更好。如果 B 明显更好，说明阶段 1 的 32 级灰度是瓶颈，反过来应改阶段 1。

### 3.3 方案 C（只有颜色）— 下限对照

$$\text{cPC}_k\ \xrightarrow{\ \text{MLP}\ }\ 96\ \text{个 RGB 值}$$

不含灰度输入。预期差，用来证明灰度输入的价值。

### 3.4 规模

| 方案 | 隐藏层 | 参数 | 乘法/样本 |
|---|---|---|---|
| A（$k=8$）| 40→128→128→96 | 约 3.4 万 | $40\times128+128\times128+128\times96 = 3.4$ 万 |
| B（$k=8$）| 12→128→128→96 | 约 3.0 万 | 3.0 万 |
| C（$k=8$）| 8→128→128→96 | 约 3.0 万 | 3.0 万 |

**都远小于灰度生成器的 74,752。** 所以彩色的增量成本不高——这对红石是好消息。

## 四、训练

| 项 | 取值 | 理由 |
|---|---|---|
| 损失 | MSE on RGB/15 | 与灰度阶段一致 |
| 优化器 | Adam | 一致 |
| 步数 | 12000 | 与灰度 dim4x 相同，保证可比 |
| 批量 | 256 | 一致 |
| 学习率 | 3e-4 | 一致 |
| 验证集 | `L0_split.npz` 的 `va` | 与灰度一致 |
| 输入标准化 | 用训练集均值/方差 | 防泄漏 |

**关于 sym 约束**：灰度那边有"镜像对称"的硬约束。**彩色先不强制镜像**，而是把对称性作为一个**测量项**。如果颜色对称性足够高（>85%），第二轮再加镜像约束以减少参数。

## 五、评估指标

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| **RGB MAE** | 96 个通道的平均绝对误差（0~15 级）| 总体重建质量 |
| **逐位置误差图** | 8×8 上的平均误差 | 看错误集中在哪里（通常是边缘/头发）|
| **饱和度 MAE** | 转成 HSV 后的 $S$ 误差 | 颜色浓淡 |
| **色相误差（循环）** | $\min(\lvert h_1-h_2\rvert, 1-\lvert h_1-h_2\rvert)$ | 色相是循环量，不能用普通差值 |
| **灰度一致性** | 预测 RGB 加权后的灰度 vs 阶段 1 的灰度 | 检验两阶段是否互相矛盾 |
| **视觉对比图** | 真实 / 预测 / 色相误差图 | 数字会骗人，图不会 |

**关键判据：色相误差。** 因为明度是免费的（阶段 1 已经给了），真正要学的是色相和饱和度。

## 六、实验矩阵

| 编号 | 方案 | 输入 | 目的 |
|---|---|---|---|
| E1 | A | $G_{32}$ only（$k=0$）| **证伪对照**：只给灰度，颜色应该很差 |
| E2 | A | $G_{32}$ + cPC 4 | 少量颜色信息 |
| E3 | A | $G_{32}$ + cPC 8 | 主方案 |
| E4 | A | $G_{32}$ + cPC 16 | 颜色信息更多 |
| E5 | B | 4 灰度 PCA + cPC 8 | 联合对照 |
| E6 | C | cPC 8 only | 无灰度对照 |
| E7 | A | $G_{32}$ + cPC 8，**加对称约束** | 如果 E3 的对称率低才做 |

**E1 是最重要的一个。** 它是"如果用户的两阶段想法错了会怎样"的对照——如果 E1 的色相误差和 E3 差不多，说明颜色 PCA 没起作用，整个设计要重想。

## 七、成功判据（事先定好，避免事后找理由）

| 判据 | 阈值 | 含义 |
|---|---|---|
| E3 的色相误差 | **< 0.10**（即平均 < 36°）| 颜色基本正确 |
| E3 优于 E1 | 色相误差降低 **> 40%** | 彩色 PCA 确实在起作用 |
| E3 与 E5 差距 | **< 20%** | 两阶段不劣于联合，可以复用阶段 1 |
| 灰度一致性 | 预测 RGB 的灰度与 $G$ 的差 **< 1.5 级** | 两阶段不互相拆台 |

**四项全过 → 两阶段方案成立，可以进红石。**
**任意一项失败 → 报告失败原因，不强行下结论。**

## 九、已知风险

| 风险 | 应对 |
|---|---|
| 颜色对称性低，强制镜像破坏数据 | 先测量；E7 只在必要时启用 |
| 色相误差用普通差值会误导 | 强制使用循环距离 |
| 321,219 样本对 96 维输出可能不够 | 用验证集监控过拟合，必要时降容量 |
| 4 bit 量化丢失细节 | 先测量化误差上限（真实数据量化后再还原的误差）|

**第四条要先做**：如果真实数据量化到 4 bit 再还原，本身误差就有 0.5 级，那么模型误差不可能低于 0.5。这个下限必须先量出来，否则无法判断模型好坏。
